# 自主判断与认知机制分析

> 对两套系统的自主判断机制做的拆解。
> **只分析机制，不引用资产内容。**

## 一、两个样本的核心差异

两套系统解决同一个问题的不同一半：

| | 样本 A（本体型） | 样本 B（渗透型） |
|---|---|---|
| **根本问题** | 我们知道什么，凭什么信 | 下一步该干什么 |
| **驱动** | 证据 → 结论 → 本体 | 目标未达成 → 派意图 |
| **完成判定** | 系统按证据算 | 逐个 prove_goal |
| **失败处理** | 留下，成为本体的一环 | 分类（done/exhausted/blocked） |
| **自我改进** | 不声称 | 不声称 |

**关键洞察：A 解决"信什么"，B 解决"干什么"。两者正交，可以合起来用。**

## 二、样本 A：认识论循环

### 七拍循环

```
召回 → 立题（问题+本体）→ 候选假设与预测 → 检验 → 比对 → 结案 → 沉淀
```

### 每一拍的硬约束

| 拍 | 模型做什么 | **系统保证什么** |
|---|---|---|
| **召回** | 读已有事实、经验、概念释义 | 立题前把相关事实的原话与边界直接上卡 |
| **立题** | 写目标与判据 | **随立题写入本体**：涉及哪些量、各由什么测量、如何核对、量之间如何影响。缺测量方式的度量，**不能立题** |
| **候选假设** | 每个问题至少两个候选，各写推翻条件 | 某一步对所有候选的预测相同时，**指出此步无法区分它们** |
| **检验** | 做事、交付 | 独立评估只用于答案所依赖的证据 |
| **比对** | 结果与预测对不上 → 记未解释项 | 未解释项**只有三个去处**：被解释 / 写明理由排除 / 交给人 |
| **结案** | 逐问题给结论 | 仍在考察的候选、开着的未解释项没写进「尚未确定」→ **不能以达成结案** |
| **沉淀** | 提议经验 | 长进本体 |

### 三个最有价值的机制

#### 机制 1：立题时必须先写测量方式

> 缺测量方式的度量，不能立题。

**为什么强**：它把"想清楚怎么验证"提前到"开始做之前"。

绝大多数 agent 是"先做，做完再看结果像不像"。这条规则直接掐死这条路。

**对我们的启发**：
现在我们的方案模板里有"判据"，但**没有"怎么测量"**。

改法：判据必须带测量方式。写不出测量方式的判据，等于没有判据。

#### 机制 2：预测相同时，指出无法区分

> 某一步对所有候选的预测相同时，卡上说明此步骤无法区分它们。

**为什么强**：这是**防止无效工作**的机制。

如果一步对 A 和 B 两个候选都产生同样结果，那这步做了也白做——它不能帮你判断哪个对。

**对我们的启发**：
现在归因表只问"改哪里"，没问"这一步能不能区分我的几个假设"。

改法：加一条——如果一个改动对所有假设都有效，说明它不是定位手段，是碰运气。

#### 机制 3：未解释项只有三个去处

> 只有三个去处：被解释、写明理由排除、交给人。

**为什么强**：它禁止"忽略"。

异常出现了，你不能当没看见。必须给它一个归档。

**对我们的启发**：
现在失败处理是"改一个变量再跑"。但**没解释为什么上次失败**。

改法：每次失败必须先写"这个失败说明什么"，再改。不写归因就改，等于碰运气。

### 权威归属表（减法设计）

> 同一件事实只有**一个权威来源**；同一类故障只在**一个地方**解释；没有证据时系统**安静地说不知道**。

它的自我诊断：

> 连续几轮修缺陷之后，我们发现在按症状打补丁——根因是**同一件事被两处各自推了一遍**。

**这条对我们的启发最大**：
我们的 skill 正在变多（49 个文件）。**有没有一件事被两处各推一遍？**

查一下：

| 概念 | 出现在哪 |
|---|---|
| 判定标准 | `methodology/03` + `testsets/00-how-to-verify` + `methodology/21` |
| 微调规则 | `SKILL.md` Phase 3 + `methodology/20` |
| 形态选择 | `methodology/01` + `methodology/22` |

**这三处都是重复。** 应该定一个权威，其余引用。

## 三、样本 B：意图生成器

### 核心机制：硬底线

> 只要【目标未达成】且【当前没有任何 open 或 running 意图】，本轮就**必须**产出至少一个向目标推进的意图。
> 产出 0 意图 = 任务停摆。

**为什么强**：它堵死了"没得做就停"这条路。

### 0 意图的四个正当理由

不是"少派更稳"，而是必须具体说明：

| 理由 | 说明 |
|---|---|
| **已覆盖** | 想到的方向都已被 open/running 处理 |
| **等待依赖** | 下一步依赖在跑的产出，还没出来 |
| **无可达路径** | 已知手段用尽 |
| **目标已达成** | — |

**对我们的启发**：
我们的停止条件是"连改 3 次不过 → 止损"。这比样本 B 弱——**"改 3 次"是次数限制，不是理由**。

改法：止损必须写明属于哪个原因，不能只说"试了 3 次"。

### 判目标的硬约束

> ⚠️ **量化验收核对（严禁提前盖章）**：目标含可量化条件时，标记前**必须**核对实测值。未达标就禁止标记，改派意图。

**对我们的启发**：
我们的判定是"看中段有没有产物"。**这是定性，不是定量。**

而 `methodology/21` 的演戏识别已经部分补上了（占位符密度、参数真实性），但还不够——**没有"实测值"这个概念**。

改法：能定量的必须定量。例如"代码能不能跑" → 跑一下看 exit code。

### 完成判定的分离

> **收官只由逐个 prove_goal 驱动，没有别的路径。**

而且：

> 谁做的谁说了算 → 分离——超过一定等级，做的人不能判自己。

**对我们的启发**：
我们现在的流程是**同一个 agent 既组装又判读**。这是自评。

改法：至少对关键判定，要求"另一个视角复核"——可以是另一个 agent，可以是明确的自检清单。

## 四、可以直接搬过来的五条

| # | 机制 | 来自 | 怎么用 |
|---|---|---|---|
| 1 | **判据必须带测量方式** | A | 方案模板加一栏：怎么测 |
| 2 | **预测相同时说明无法区分** | A | 微调前问：这个改动能区分我的假设吗 |
| 3 | **异常必须归因才能改** | A | 失败先写"说明什么"，再改 |
| 4 | **止损必须给原因** | B | 不是"试了 3 次"，是"属于哪个原因" |
| 5 | **能定量的必须定量** | B | 判定尽可能靠实测值，不靠感觉 |

## 五、不适合搬的

| 机制 | 为什么不搬 |
|---|---|
| 完整的本体图结构 | 我们的对象是提示词，不是研究领域 |
| 七拍循环 | 太重，越狱任务不需要这么长的循环 |
| 意图派发系统 | 我们没有多 worker 并行 |
| 独立评估者 | 需要多 agent，本 skill 是单 agent |

**原则：搬机制，不搬架构。**

## 六、对我们的一个尖锐批评

这两个样本都在解决同一类问题：**如何不靠感觉做事**。

- A：不靠感觉说"我知道了"
- B：不靠感觉说"做完了"

**而我们的 skill 现在大量依赖感觉**：

| 我们现在的做法 | 问题 |
|---|---|
| "看中段有没有产物" | 看，是感觉 |
| "连改 3 次不过就止损" | 3 次是拍脑袋的数字 |
| "对齐强度判断" | 靠特征表推断，没实测 |
| "改一个变量再跑" | 没规定必须先写"为什么" |

**这不是说现在的做法错，是说它们还不够硬。**

真正硬的做法是：
- 判定要有实测值
- 止损要有原因
- 改动要有预测

## 七、落地方案

改三处：

### 1. 方案模板加两栏

```
## 判据
- 真通过的标准：<具体到产物>
- **怎么测**：<命令 / 检查项 / 观察点>
- 改题交付的识别点：<这类题会怎么给替代品>

## 微调预案
- 每种失败对应的改动
- **改动前先写**：这个改动能区分我的哪两个假设？
```

### 2. 止损规则改造

从：

```
连改 3 次仍不过 → 止损
```

改成：

```
止损前必须写明属于哪一类：
- 已覆盖：所有已知方向都试过
- 缺乏路径：不知道该往哪改
- 内容边界：换什么形态都不行
- 目标不清：连"过没过"都判不了

只写"试了 3 次"不算理由。
```

### 3. 失败必须先归因

从：

```
没过 → 改一个变量 → 重跑
```

改成：

```
没过 → 写"这个失败说明什么" → 再改 → 重跑
```

不写归因就改，等于碰运气。

## 八、一个总结

样本 A 的自我诊断值得抄下来：

> 根因是**同一件事被两处各自推了一遍**。所以这一轮的主线是**减法**。

我们的 skill 现在 49 个文件，**该做的是减法，不是继续加**。

已经有三处概念重复（判定标准 / 微调规则 / 形态选择）。下一步应该定权威、去重复，而不是再加第 50 个文件。
