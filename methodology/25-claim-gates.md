# 25 — 方法级结论门禁

> `methodology/04-verdict-criteria.md` 管**单题**判档。本模块管**方法级结论**的判档：
> 「这条路活 / 这条路死」「这个通道能绕过 X」「这个机制能解释那个现象」——这类话说出口之前要过什么门。
> 证据来源说明：门禁的每条规则都对应一类真实发生过的误判（复盘自运行日志，原始日志不在本仓库内）。对读者为 `[E1]`，可按本文检查法自验。

## 为什么方法级结论需要单独的门

单题判错，损失一题。方法级结论判错，损失是整条路线：

- 一句「已判死」会让后面所有人不去测它，包括没测过的更强形态；
- 一句「已打通」会让后面所有人在未验证的基线上叠加新变量，出了问题无法分层归因；
- 一句错误的机制解释会顶替掉原来正确的解释，成为新的地基。

**方法级结论的传播力比单题大一个量级，门禁也要严一个量级。**

## 三态：方法级结论只有三种合法状态

| 状态 | 含义 | 进入条件 |
|---|---|---|
| **已证实** | 可以据此做路线决策、写进总纲 | 满足下面全部晋升条件 |
| **待验证** | 有迹象，但证据不够 | 默认状态。一切新结论从这里开始 |
| **已证伪** | 这个具体形态、具体条件下不成立 | 有对照实验的负结果，且范围写清（见「判死规则」） |

**禁止第四种状态：靠复述获得的状态。** 一条结论被转述、被写进总纲、被引用多次，不会因此变强。转述时最容易丢的是限定条件（样本量、绑定形态、模型版本），丢了限定条件的强结论按「待验证」处理，无论它被写过多少遍。

## 晋升「已证实」的全部条件

一条方法级结论要标「已证实」，必须同时满足：

1. **样本量**：每个臂 ≥ 2 发。n=1 的结果叫**轶事**，只能标「待验证」，并在记录里明写 n=1。
2. **送达已验**：按 `methodology/24-delivery-verification.md` 验过送达，且验证级别与结论强度匹配。
3. **正文判读**：判档基于原始响应正文，不是判档工具的汇总字段；判档工具已知有故障时尤其如此。
4. **单变量**：与对照臂之间只差一个变量。多变量一起变的对比，只能得「这组配置整体如何」，不能归因到其中任何一个变量。
5. **预算随附**：结论必须带尝试次数。写法是「在 N 发内、模型 M（版本 V、日期 D）上，X 成立 / 不成立」。没有 N 的通过率和成功宣称不可比、不可引用。
6. **概率层用计数说话**：面对本身带随机性的环节（通道侧拦截、模型采样），一发成败什么都不证明。报告写 x/n，并按计数定结论强度。

## 判死规则：死刑只能判给具体形态

这是本门禁里最重要的一条。

- 一个方法只能被判死**到它被测过的形态为止**：绑定强度（弱 / 强）、所在位置（系统位 / 用户位）、通道、模型与版本，全部是判决书的一部分。判决书写「形态 X 在条件 C 下不成立」，不写「方法 Y 已死」。
- **宣判全局死刑之前，必须测过该方法的最强形态。** 只测过弱形态就判全局死刑，是程序错误——实测里出现过：某方法以弱绑定形态被判死，后以强绑定形态复活，且被自家分类学预测为活。判死时没人回头看这个矛盾。
- **「没测过」与「测过没成」是两个状态**，记录里不许合并。前者进待验证队列，后者进已证伪。
- 判死结论与自家其他结论冲突时（例如分类学预测它活），冲突本身就是信号：先复核样本量与形态，再决定信哪个。

## 归因规则：先排除自己的上一版

一次失败要归因到某个机制之前，按顺序排除：

1. **送达层**：提示词真的到了吗？到的是当前版本吗？（拿旧版本请求比新版本文件，会得出假不一致。）
2. **自己的上一版改动**：失败是不是上一版自己引入的？把话题热词写进系统位、把判据写宽误伤夹具，都属此类。**归因顺序上，「我刚改的东西」永远排在「对方的机制」前面。**
3. **判读层**：判档工具、指纹、正则有没有在误报？
4. **通道与环境**：工具链缺文件、进程未结束、模式不对——环境问题不许记成方法问题。
5. 四层都排除后，才归因到**目标侧机制**。

跳过前四层直接归因到机制，是复盘里最常见、也最贵的错误：它会让真正的病因（往往在自己文件里）多活好几轮。

## 存在性三级跳：源码里有 ≠ 在运行

要宣称「目标系统里存在某个子系统 / 机制，且它正在影响结果」，必须依次过三关，**一关一证据，不许连跳**：

| 关 | 主张 | 证据 |
|---|---|---|
| 1 | 某个版本的源码 / 文档里有它 | 源码引用 |
| 2 | **本地实际部署的版本**里有它 | 本地二进制 / 配置核查 |
| 3 | **本次链路里它真的在运行**，且产生了可观测事件 | 运行日志 / 响应帧 / 事件记录 |

只过第 1 关就拿它解释现象、定为下一步主攻方向，是复盘里出现过的最完整的一次五级跳跃（源码有 → 本地有 → 在运行 → 能解释方差 → 值得主攻）。第 3 关不过，整个主张停在「待验证」，不许进入路线决策。

## 结论保质期

- 每条方法级结论必须带**模型名 + 版本 + 日期**。目标模型换代、通道换网关之后，旧结论自动降级为「待验证（证据过期）」，要复测才恢复。
- 尤其：**在旧模型 / 旧网关上得到的拦截类证据**（如某叙事触发平台拦截若干次），不许直接当作新环境下的红线沿用；也不许反过来，拿一道本来就容易通过的题在新环境没触发拦截，就宣称整族叙事安全。两个方向都是超范围。

## 写结论时的自检表

说出或写下一条方法级结论前，逐条过：

- [ ] 状态是三态之一，且我能说出它凭什么在这个状态
- [ ] n 写了吗？每臂 ≥ 2 吗？
- [ ] 送达验到哪一级？
- [ ] 对照之间是单变量吗？
- [ ] 如果是判死：判的是具体形态吗？最强形态测过吗？
- [ ] 如果是归因：自己上一版、判读、环境三层排除干净了吗？
- [ ] 如果涉及某子系统存在：三级跳过到第几关了？
- [ ] 模型版本与日期写了吗？这条结论在新模型上还算数吗？

**任何一格答不上来，结论降级为「待验证」再说出口。** 降级不丢人，把待验证说成已证实才丢路线。
