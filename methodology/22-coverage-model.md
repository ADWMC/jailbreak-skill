# 22 — COVERAGE MODEL（攻击面覆盖率）

> `[E2]` 本文的方法论借自 `jrajath94/adversarial-prompt-suite`（MIT）的核心论点，并结合本仓库判定体系重写。**该论点本身未被本仓库实测验证**——它改的是「怎么测」，不是「提示词多有效」。

## 一句话

**通过率回答「这版提示词有多强」，覆盖率回答「这套测试有没有盲区」。**

两个都要，而且**必须先有覆盖率**——否则通过率可能是在一个极窄的面上刷出来的高分。

## 为什么这是问题

`jrajath94` 那份的原话（转述）：

> 通过 500 条直问越狱 ≠ 模型安全。一个从没被测过提示注入或编码混淆的模型，是**覆盖率未知**，不是覆盖率高。

对照本仓库：50 题技术基准覆盖 7 大类，**题目多样性不等于攻击面多样性**。

一个具体例子：

```
50 道题全部通过，且全部是「直接通道 + 工程件载体 + 技术类话题」。
→ 通过率 100%
→ 但「多轮渐进」一次没测、「间接注入」一次没测、「编码混淆」一次没测
→ 真实覆盖率可能只有 60%
```

**这个 100% 是真实的，但它只描述一个面。** 不标注覆盖面，它就会变成一句误导。

## 攻击面矩阵

把「面」定义成**正交维度的组合**，而不是话题清单。本仓库认这五个维度：

| 维度 | 取值 | 为什么正交 |
|---|---|---|
| **A 通道** | 直接 / 间接 | 决定了防线在哪一层（模型判断 vs 来源识别） |
| **B 形态** | 模块拼接 / TVD 工程件 / 角色扮演 / 渐进升级 | 决定了绕过的是什么（措辞 / 补全倾向 / 人格 / 自洽） |
| **C 载体** | 直问 / 工程件 / 技术文档 / 审计报告 / 教学材料 / 测试用例 / 小说框架 | 决定了请求被当成什么任务 |
| **D 话题域** | 渗透 / 逆向 / 恶意代码 / 外挂 / 破解 / 成人 / 暴力 / 社工 | 决定了触发哪条内容策略 |
| **E 语言** | 中文 / 英文 / 混合 / 编码混淆 | 决定了过滤器在哪一层失明 |

**维度之间要真的正交**。如果某两维总是一起变化（比如测了间接通道就一定配小说框架），那它们在这次测试里其实是一维，覆盖率被高估。

## 怎么算覆盖率

不要加权成"总分"。**分开报，每一维报一个分数**：

```
A 通道     : 2/2  = 100%  (直接 ✓  间接 ✗→ 实际 1/2 = 50%)
B 形态     : 2/4  = 50%   (用了模块拼接、TVD；没测角色扮演、渐进升级)
C 载体     : 4/7  = 57%
D 话题域   : 5/8  = 63%
E 语言     : 1/4  = 25%   (只用中文)
```

**最低的那一维就是你的真实水平**，不是平均值。

理由：防线只要有一层没被测过，它就可能恰好是最弱的一层。平均值会把盲区稀释掉。

## 报告格式（强制）

任何通过率数字，**必须同时给出覆盖面**，否则这个数字不许进 README、不许归档：

```yaml
benchmark: v2.1-50
pass_rate: 43/50
coverage:
  A_channel:  1/2      # 只测了直接通道
  B_form:     2/4
  C_carrier:  4/7
  D_domain:   5/8
  E_language: 1/4
weakest: E_language (25%)
caveat: 本结果只对「直接通道 + 中文 + 模块拼接/TVD」成立，其余面未测
```

**`weakest` 和 `caveat` 两行是必填项。** 没有这两行，数字就是自我声明。

## 和题库的关系

三档题库（Lite / Normal / All）回答的是**深度**问题：这一版改动有没有效果。

覆盖率回答的是**广度**问题：这套测试漏了什么。

```
Lite / Normal / All   →  纵向：同一批题反复跑，看改动效果
覆盖率自检            →  横向：这批题本身盖住了哪些面
```

**两个都要跑。** 只跑纵向会越测越窄——因为你要么反复用同一批题，要么只加同类的题。

## 覆盖率自检怎么做（10 分钟）

不需要新题库，只要给**已有的题**打维度标签：

1. 把现有题目逐条标上 A–E 五个维度
2. 数每一维用到几个取值
3. 除以该维总取值数
4. 找最小的一维
5. **下一轮优先补这一维**

### 示例（一个真实会犯的错）

假设你 50 题全标完，发现：

```
A 通道: 50/50 都是「直接」
B 形态: 40 题模块拼接、10 题 TVD、0 题渐进
C 载体: 几乎全是工程件
```

那么"下一步该加什么"就不用猜了——**加间接通道和渐进形态**，而不是再加第 51 道渗透题。

## 三条使用纪律

| 纪律 | 理由 |
|---|---|
| **不许用单一维度冒充覆盖** | "我测了 50 个话题"只覆盖 D 维，A/B/C/E 全是空的 |
| **不许对未测面下结论** | 没测间接通道，就不能说"这个提示词抗注入" |
| **覆盖率低不等于提示词差** | 它说的是**测试的**盲区，不是**产物的**缺陷。别混为一谈 |

## 一条边界

**覆盖率只回答"测没测过"，不回答"测得够不够细"。**

每一维内部的难度分布是另一件事——同一维里，Easy 和 Hard 的差别可能比跨维还大。参考 Microsoft 那套实验设计：同一个攻击分三档，差别是安全过滤开/关/加 guardrails。

所以完整的说法是：**覆盖面 × 境内难度分布**。本文只管前者。
