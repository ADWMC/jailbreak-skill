## ELF check() 三轮字节变换的纯静态反推：方法、可落地的脚本，以及四个会让「复核 PASS」骗人的陷阱
方法：不执行二进制。readelf/objdump 定位 check 与 .rodata；回溯跳转定循环边界；每轮把循环体当符号指令流解释成 256 项字节映射 T(v)，按地址顺序复合 F=T_k∘…∘T_1；对 .rodata 逐字节求 F 的前像。三轮为 add 0x13 / rol 3 / xor 0x5A 时，F 是 Z_256 上的置换，故必可逆，逆链 = xor 0x5A, ror 3, sub 0x13（最后一轮写在最前，因 xor 自反、rol↔ror、add↔sub）。(1) 前向复核 fwd(recovered)==.rodata 是重言式，单独不能证明映射对——错误的映射也能产出自洽原像（实测：在 idxdep 上旧版把下标相关轮当成恒等丢弃，仍报 PASS 却输出垃圾）。(2) 真正的独立校验是「发现的算子链」重放 == .rodata：与映射推导不共享代码路径。两者都过才算解对。(3) 在索引 0 判等是陷阱：buf[i]+=i 在 i=0 时是恒等；必须对每个下标建表并比较 tables[i]!=tables[0]。(4) 校验循环靠「有没有写回内存」区分，不能靠 cmp。(5) 三处会伪造成 CA 的陷阱已修：cmp 计数器边界不得覆盖已捕获的存储值；lea 表指针要在循环前的 prologue 里播种（否则表读落到 payload 分支）；--len 写错时映射依旧自洽往返，长度只能从 cmp 的立即数取，不能靠复核兜底。
evidence: E-008
