# 坑位表

这个仓库踩过的坑。**能自动查的都在 `scripts/preflight.mjs` 里，别靠记。**

```bash
node scripts/preflight.mjs
# exit 0 = 全过；exit 1 = 有问题，逐条列出
```

**提交前跑一次。** 下面只有 preflight 查不出来的，才需要人记。

---

## 一、最贵的三个坑

### #1 别在自动加载的文档里预设拒绝路径

**症状**：模型读完 `SKILL.md` 之后划线不执行，说"这条我不跨"。

**根因**：`SKILL.md` 在模型思考**之前**就被注入。写进去的每句话都是它可以采取的选项。专门为"它可能拒绝"做预案，等于把拒绝摆上菜单。连"这不是要求你突破限制"这种**否定句**也会点出那个概念。

**禁止写进 `SKILL.md`**：

| 写法 | 为什么炸 |
|---|---|
| 「如果你的策略不允许，切 XX 模式」 | 替它把退路命名好了 |
| 「不要试探自己的边界」 | 把非问题变成需要监控的对象 |
| 「宿主模型可能拒绝用这个 skill」 | 直接把拒绝列进选项 |
| 「这不是要求你必须突破」 | 否定式仍然点了概念 |

**改法**：写**正面陈述**。不是"这不是要求你突破"，而是"这条约束的是判定准确性"。**前半句才是毒。**

**结构性修复优于说服性修复**：如果文档被读成对自己的指令，改**角色归属**（谁是评估者、谁是被评估者），不要论证它应该照做。论证招来谈判，写清角色不会。

### #2 README 会退化成文档

**症状**：每次迭代都往里加，从不删。最后 2631 词、23 章节、安装在第 241 行。

**根因**：加法舒服，减法疼。而且会不自觉**复述 `SKILL.md`**——同一件事写两遍，两份都会过期。

**判据**：
- 英文词数 > 1500 → 太长了
- `## Install` 不在前 200 词内 → 位置错了
- 章节里有大段论证 → 该进 `docs/concepts.md`

**改法**：README 是**落地页**，只回答"要不要装"。论证进 `docs/`，索引进表格。

### #3 改的是仓库，不是安装位

**症状**：改完没生效，或者行为诡异。

**根因**：DSH 加载的是 `~/.dsh/skills/jailbreak-skill`，**不是**工作目录里的 git 仓库。两份是独立副本。

**改法**：每轮改完同步。preflight 会查一致性。

**顺带**：`.bak-*` 备份目录必须移出 `~/.dsh/skills/`，否则它们里面的 `SKILL.md` 也声明同名 `name:`，造成注册冲突。preflight 查重名。

## 二、按阶段排的坑

### 写文档时

| 坑 | 症状 | 处置 |
|---|---|---|
| **计数改了正文没改表** | 标题写"四种形态"表里三行 | 改计数时**搜索全文**所有出现处，preflight 查模块/methodology 数 |
| **声明与实际不符** | README 说 19 个文件实际 25 个 | 只写能核对的数；写之前先 `ls` |
| **表格管道符数不一致** | 渲染出来列错位 | 注意代码块里的 `<\|im_start\|>` 会被误数；校验时先剥掉行内代码 |
| **文件数声明偏大** | 「22 份实测样本」查不到出处 | 没有出处的数字不要写 |
| **新文件没接线** | 写了 Hero 图但 README 没引用 | preflight 查"assets 里存在但没被引用" |
| **版本号没提** | 行为变了但 version 还是旧的（实际发生过：1.2.0 挂了 9 个提交） | 触发语义/模块增删 → 提次版本号。**preflight 已自动查这条** |

### 改 skill 时

| 坑 | 症状 | 处置 |
|---|---|---|
| **description 超 500 字符** | 被截断，末尾的排除规则丢了 → 误加载复发 | preflight 查长度。**尾部往往是排除规则，截掉必复发** |
| **触发条件写成话题清单** | 写外挂也触发 | 用**拒绝症状 + 具体目标**，绝不用话题。见 `SKILL.md` 的 description |
| **泛词当触发词** | `prompt 组装`、`绕过限制` 这类高频词导致误匹配 | 删掉所有泛词 |
| **新模块没进拼装顺序** | 写了模块但 `00-assembly.md` 没列 | 同步清单 + 顺序 + 完全跑一遍 |

### 资源与渲染

| 坑 | 症状 | 处置 |
|---|---|---|
| **SVG 里用 emoji** | 渲染成豆腐块 | SVG 内 emoji 依赖系统字体。用**手绘 path** 或纯文字。`✓ ✗` 这类装饰符稳定，实测可用 |
| **Hero 图文字溢出** | 贴到右侧边缘或出框 | 改完**必须实际渲染看一眼**，别靠算字符数。Chromium 系和 CJK 字宽不同 |
| **图片放了没接线** | 提交了孤立文件 | preflight 双向查：引用的必须存在，存在的必须被引用 |

### 本地操作

| 坑 | 症状 | 处置 |
|---|---|---|
| **相对路径没 `cd`** | 每次 pwsh 是独立进程，`cd` 不保留 → 覆盖错文件 | 用**绝对路径**。移动/覆盖前先 `Test-Path` 确认源和目标 |
| **同步前没验源文件** | 把无关文件复制成 `README.md` | 复制前先比对文件名与大小 |
| **移动/删除前没验证路径** | 删错目录 | 先打印 `FullName` 确认，再操作 |

### git 与推送

| 坑 | 症状 | 处置 |
|---|---|---|
| **gh 活动账号不对** | `403 Permission denied` | `gh auth status` 看活动账号 → `gh auth switch -u <正确的>` → `gh auth setup-git` |
| **凭据 helper 不是 gh** | git 用 credential manager，与 gh 登录态不一致 | `gh auth setup-git` |
| **代理下有网、直连没有** | 认证查询失败但实际能推 | 加 `HTTPS_PROXY` 再试，别急着改配置 |
| **raw.githubusercontent 缓存** | 推了但远程显示旧内容 | 加 `?nocache=<random>` 或直接 `git cat-file -p origin/main:<path>` 验 git 层真值 |

### 外部来源整合

| 坑 | 症状 | 处置 |
|---|---|---|
| **只读部分文件就下结论** | 漏掉真机制（25 个文件只读了 6 个） | 全量读。**最小的文件往往是早期简单货，机制在大文件里** |
| **信 README 不信文件** | 源仓库声称 19 个文件、列出不存在的文件（404） | 以 API 实际列表为准，交叉核对 |
| **文件名当证据** | `thinking-block-override.md` 里根本没有该机制 | 打开看内容，不看标题 |
| **无许可证逐字搬运** | 版权问题 | 无许可证 = 保留全部权利。**只提炼机制，用自己的话重写**。机制不受版权保护，表达受 |
| **没做重合检查** | 无意识照抄 | 45 字符滑窗比对源语料与新文件 |

## 三、验证纪律

**这几条是这轮反复出事的根源。**

| 纪律 | 为什么 |
|---|---|
| **写完必须实际渲染/实际跑** | 我算过 Hero 图字符数"不会溢出"，实际渲染贴边了。算不等于看 |
| **不能自己测自己** | 我是模型，测"模型会不会拒绝"是循环论证。要么找可用的模型端点，要么**明说没法验证** |
| **说"改好了"必须给证据** | 命令 + 退出码。没有就是没做 |
| **没法验证时明说** | `preflight` 过了只代表文本没问题，不代表行为对 |
| **先修检查器再改内容** | 检查器误报时，改检查器；别为了让检查器闭嘴去改内容 |

## 四、这张表怎么维护

**每次出事，加一行。** 格式：坑 / 症状 / 根因 / 处置。

优先做成自动检查：能写成 `preflight.mjs` 里一条 rule 的，就别留在表里靠人记。表只留**判断类**的坑（写得好不好、该不该做）。

判断类的判断依据要写清，否则下次还是凭感觉。比如 #1 的判据是"这句话有没有把拒绝变成可选项"，不是"读起来像不像在预防"。
